# 2026-07-13 开发日志

## 今日目标

将本地 AI MVP 工作流升级为低 token 的受监督开发流程，强制生成中文开发记录和 AI 可读项目文档，并在本地模型异常时由看门狗自动切换 Codex 接管。同时准备安全的 Git/GitHub 交付信息。

## 今日进展

- 将 Skill 默认输出从详细实时模式调整为简洁模式，Codex 对话只保留启动、心跳、Review、接管和最终状态。
- 增加本地模型看门狗：启动失败、命令失败、总超时或连续 300 秒没有结构化进展时，终止本地进程并调用 Codex 监督者接管。
- 为编码、修复、Review 和监督者提示词加入中文文档要求。
- 增加文档契约校验，缺少文档、中文内容不足、章节不完整或本次未更新都会阻止交付。
- 在 `summary.json` 中加入安全的版本管理快照，为用户验收后的 GitHub 发布做准备。

## 修改内容

- `src/mvp_orchestrator.py`：增加空闲超时、看门狗接管、中文文档校验和版本快照。
- `config/defaults.toml`：增加 `local_stall_timeout_seconds = 300`。
- `prompts/`：要求本地模型与 Codex 接管者同步维护中文日志、项目大纲和任务规划。
- `templates/AGENTS.md`：加入每次开发都要更新文档的仓库规则。
- `tests/test_orchestrator.py`：增加文档契约、停滞终止、接管、版本快照和遥测噪声测试。
- `~/.codex/skills/local-ai-mvp-builder/`：更新 Skill 工作流、文档规范和低 token 策略。

## 使用方法

默认使用简洁输出：

```bash
python3 ~/.codex/skills/local-ai-mvp-builder/scripts/run-supervised.py \
  --project "/项目绝对路径" \
  --plan "/计划绝对路径.md" \
  --model primary
```

需要在终端查看详细事件时增加：

```bash
--display live
```

用户验收后，可以明确要求“上传 GitHub”；此时才进入提交、推送分支和创建 PR 的流程。
