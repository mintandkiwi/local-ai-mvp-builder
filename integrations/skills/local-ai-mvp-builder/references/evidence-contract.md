# Run evidence contract

`summary.json` preserves legacy status/review/validation/version-control fields and adds:

- `usage.stages`: one record per agent invocation with stage, backend, role, input/cached/output/reasoning Tokens, total, measurement (`exact`, `partial`, `unavailable`), duration, and exit code.
- `usage.cloud_lower_bound`: sum of measured cloud totals only. Unknown usage is `null`, never zero.
- `usage.measurement_complete`: true only when every invoked stage has exact JSON usage.
- `usage.budget`: configured soft Token budget, maximum calls, and conservative status. Incomplete data cannot be `within_budget`.
- `workflow`: cloud call count, takeover reason/round, validation counts, finding counts, risk route, and failure category.
- `risk`, `preflight`, and `context_capsules`: declared/defaulted risk, redacted structured success/failure records for model-free host gates (reviewer version, required CLI capabilities, schema readability, and repository-read probe), and bounded redacted navigation evidence.
- `efficiency.claim`: `no_baseline` for ordinary runs. Only an separately approved, equivalent, completely measured direct-cloud comparison may produce `measured_saving`, `inconclusive`, or `regression`.

JSON `turn.completed.usage` is exact only when every present supported field is a non-negative true integer; booleans, strings, collections, negative values, and malformed optional fields make the JSON measurement unavailable. A legacy `tokens used` footer is total-only `partial`. Missing, damaged, timed-out, or changed output formats are `unavailable`. Each stage retains the child process's real exit code; a well-exited but malformed structured artifact records exit 0 with a tool-result failure classification.

All persisted command/validation logs, structured review files, and agent last-message files parse valid JSON/JSONL before plaintext fallback, recursively remove sensitive subtrees (including camelCase credentials), and then apply quoted-field, multiline YAML, modern-token, private-key-block, and private-remote redaction. Numeric usage telemetry remains intact, including the real child exit code when later evidence persistence fails. A bounded capsule may truncate navigation excerpts, but it retains plan/risk plus `evidence_base_dir` and hashed sibling references for complete redacted scope, per-log validation manifests, and structured review evidence. Scope also binds a cryptographic snapshot of staged, unstaged, and all untracked content captured after successful validation. Git status/diffs and regular files are hashed in fixed-size chunks with domain-separated length and digest fields, so large artifacts are not retained whole in memory; the orchestrator verifies the snapshot before and after review and immediately before ready handoff. `review_evidence_role=prior_review_input_not_current_verdict` marks that review artifact as the previous round's finding input rather than the current snapshot's verdict. Consumers verify every SHA-256 and content snapshot before use; any mismatch is blocking.

Validation never exposes pre-existing repository or linked-worktree Git metadata. Before entering Seatbelt, the controller enumerates every root/nested `.git`, then copies allowed blobs from original HEAD into a parentless synthetic HEAD and allowed blobs from the current index into a synthetic index, both stored in the private validation directory. The live worktree is not committed, so staged, unstaged, untracked, cached diff, and diff-check results remain observable. A wrapper routes ordinary target-project paths to this history-free, remote-free `GIT_DIR`; `init`/`clone` targets and child repositories created during validation use normal per-working-directory discovery, including `git -C`. Seatbelt denies all enumerated pre-existing `.git` paths, including configs, `FETCH_HEAD`, reflogs, hooks, worktree/module metadata, and historical objects.
